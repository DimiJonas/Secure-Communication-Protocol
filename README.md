# Implementation of a Secure Handshake Protocol

This repository contains an implementation of a secure handshake protocol for authentication and agreement of cryptographic configurations and related security association parameters. It is based on UDP.
Its written in Java and Supports most cryptographic algorithms found in BouncyCastle cryptographic library. Those include block- and streamciphers and elliptic curve cryptography. Those cipers are used to provide
password-based encryption methods, public-key cryptography, digital signatures and Diffie-Hellman key agreement.

It consists of a client and a server program. Clients can choose their secutiry parameters for the key agreement and the following encrypted communication (see `src/main/test/resources/regularconfigfile.txt` as an example). A client ahs to authenticate at the server first. To setup this up a client has to generate an asymmetric key-pair and the server has to know this client (an entry in its client database). This can either be done by hand of automatically by using an additional `AddUserApplication`. The servers database contains entries in the following form:
user-id : hashed password : salt : pubkey

When client and server then want to communicate the program automatically negotiates security parameters for them in a secure handshake and then the encrypted UDP channel is created. The protocol supports TFTP, multicast and streaming applications. Test applications can be found in `src/main/java/applications/`.

The handshake protocol is called **SHP** (Secure Handshake Protocol) and the transfer protocol for the resulting data transfer is called **DSTP** (Datagram-based Secure Transfer Protocol).

## Message Flow

The handshake exchanges messages in the following way:

client -> server (msg 1)

client <- server (msg 2)

client -> server (msg 3)

client <- server (msg 4)

client -> server (msg 5)

The 5 messages contain the following parts:

- **msg 1**: userID
- **msg 2**: Nonce1 , Nonce2 , Nonce3
- **msg 3**: PBEH(passwrod), Salt, Counter (request, userID, Nonce3+1, Nonce4 , UDP_PORT), ydh-client, DigitalSignatureKprivClient (movie, userID, Nonce3+1, Nonce4 , UDP_PORT, ydh-client), HMACkmac (Total_Message)
  - Ydh-client: public Diffie-hellman number, dynamically generated by the client for a Diffie-Hellman agreement with the Server
- **msg 4**: Ekpubclient (request-confirmation, Nonce4+1, Nonce 5, crypto config),Ydh-server, DigitalSignatureKprivServer (request confirmation, userID, Nonce4+1, crypto config, Ydh-sever) HMACkmac (Total_Message)
  - Ydh-server: public Diffie-hellman number, dynamically generated by the server for a Diffie-Hellman agreement with the Client
- **msg 5**: Eks (”GO”, Nonce5 + 1), MACKmac (Eks (”GO”, Nonce5 + 1))
  - this message type is just a synchronization message

## Setup

Do the following steps to use the protocol.

### Generate Keypars for Client and Server

For generating the keypars for client and server the class `GenerateKeypairApplication` is provided
Generate the jar-with-dependencies by running `mvn clean package -DskipTests` and then run the Keygeneration for
client and server respectively with the following command:
`java -cp target/PA2-1.0-jar-with-dependencies.jar util.GenerateKeypairApplication <client|server> <optional: curve algorithm>`
This will create the files `resources/pa2/client/ClientECCKeyPair.sec`, `resources/pa2/client/ServerECCPubKey.txt` and `resources/pa2/server/ServerECCKeyPair.sec`.

### Populate the User Database on the Server

To populate the `userdatabase.txt` file in `resources/pa2/server` one can either put in the entries manually or
use the class AddUserApplication to add a users. The application asks for userid, password and public key, but
will also just generate any of those if the input is left empty.
Usage: `java -cp target/PA2-1.0-jar-with-dependencies.jar util.AddUserApplication`

### Run an Application

Each test application has its own README.txt file that contains instructions to start client and server.
See

- `src/main/java/applications/StreamingService/README.txt`
- `src/main/java/applications/TestMulticast/README.txt`
- `src/main/java/applications/TFTP-master/TFTP-master/README.txt`
